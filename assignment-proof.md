# Assignment Proof Matrix

This is the live evidence ledger for [`assignment.md`](assignment.md). It maps
the assignment's requirements to current implementation and promoted evidence.
It is intentionally more detailed than `REPORT.md`, which must remain a concise
seven-section submission narrative.

Status meanings:

- **Satisfied** — implemented and supported by tests or promoted run evidence.
- **Partial** — meaningful implementation exists, but part of the stated
  requirement is absent or unproven.
- **Missing** — no adequate implementation or evidence exists yet.
- **Design-only** — the assignment asks for design rather than implementation,
  and the documented design addresses it.

## End-to-end vertical slice

Section 5 asks for one thread spanning goal, genuine LLM discovery, saved
artifact, deterministic replay, exceptional outcomes, live human handoff, and
evidence.

**Status: Partial.** The Dolibarr corpus proves goal-driven external-LLM
computer use, draft extraction, reviewed artifact authoring, deterministic
success, typed outputs, two business outcomes, an intervention result, and
promoted traces. It does not prove a person taking over and returning the same
live browser session. That missing integration keeps the complete vertical
slice from being satisfied.
